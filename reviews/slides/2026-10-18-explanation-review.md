## 기술 정확성 검토 기준

Watermark의 5초는 원문 예시 가정이며 일반 공식이 아니다. 늦음 판정과 window 처리 결과를 분리하고 실제 policy 없이 포함·폐기를 단정하지 않는다. 여러 활성 입력의 최소 진행과 idleness를 같이 설명한다. 검토 시 [Flink stable watermark 문서](https://nightlies.apache.org/flink/flink-docs-stable/docs/dev/datastream/event-time/generating_watermarks/)를 확인했다.

SG/NACL은 동일 기준과 요청의 두 경계로 비교한다. 연결 상태 추적 여부와 응답 트래픽 규칙의 차이는 [AWS VPC 비교](https://docs.aws.amazon.com/vpc/latest/userguide/infrastructure-security.html)를 확인했다. SG 허용은 라우트 존재를 보장하지 않는다.

Schema Break는 가능한 영향 경로이며 모든 단계의 실패를 단정하지 않는다. 자동 타입 변환과 업무 의미 보존을 구분한다. 영어 check는 뜻·직접 목적어/check whether·업무 예문을 함께 유지한다. 프롬프트 출력은 예시 형태이며 실제 모델 응답이나 운영 결과가 아니다.

## 확장 정책과 검증 한계

전체 문서 발견·로딩은 설명 품질과 별도로 보고한다. 검토된 대표 설명만 명시적 설명 데이터로 제공하고 나머지는 정적 원문이다. 원문이 바뀌면 검토 데이터의 출처 결합과 의미를 다시 확인한다. 상호작용 추가에는 정적 설명보다 나은 점, 가정, 독립 입력/기대 결과, 한영 검토와 화면 검증이 필요하다. 원문 행 매핑률·생성 개수·필드 수는 품질 판정에 쓰지 않는다.

화면 읽기 프로그램의 실제 음성 출력, 실제 iOS/Android 브라우저의 주소창 변화, 사용자 이해도 향상은 별도 실사용 검증 대상이다. 자동 브라우저 결과를 이 범위의 통과로 확대하지 않는다.

## 한영 의미 대응 검토

대표 절의 한영 원문과 생성 설명을 대조했다. Watermark는 정의·10:01:10/5초/10:01:05 예시·10:01:03 설명용 입력·late 정책·비용·idleness 제한을 공통 `watermark` 단위로 묶는다. SG/NACL은 적용·stateful·allow·deny 및 SG 참조/합집합/라우팅 제한, Schema Break는 타입 변경·가능한 경로·대응·예방·타입/값/건수/downstream 검증을 대응시킨다. check는 뜻·용법·같은 업무 문장과 번역, prompt는 용도·입력·기대 출력 형태·원문 한영 요청을 유지한다.

`slide_sections.json`의 전체 절 대응은 초기 한영 제목 구조에서 등록한 식별자이며 전체 문서 의미 검토를 뜻하지 않는다. 런타임에는 각 언어의 원문 절을 독립 조회한다. 제목이 변경되거나 새 절이 생기면 명시적 anchor 또는 등록 검토가 필요하며 모르는 절은 unpaired다. 검토 설명 원문 SHA가 바뀌면 정적 원문으로 돌아가 재검토를 요구한다.

## 직접 디자인·조작 검토

수정 전 Watermark 모바일의 좁은 본문과 카드 중첩, SG/NACL 데스크톱의 빈 왼쪽 영역을 그림으로 확인했다. 수정 후 Watermark 320×568은 전체 본문 폭을 쓰고 처음부터 정의와 두 시간 순서의 차이를 보여 준다. 390×844 타임라인은 수치 가정, 도착 순서와 이벤트 시각, 진행 기준과 late 판정을 같이 보여 준다. SG/NACL 320×568은 기술 이름과 공통 기준이 함께 보인다. 같은 페이지의 인접 행은 한 표로 묶고, 페이지가 나뉠 때 머리글을 반복하여 셀의 소속을 유지한다. Schema Break 390×844의 방향 있는 연결 경로와 “모든 단계가 반드시 실패하지 않는다”는 한계를 직접 읽었다.

차분한 중립색·진한 본문·한 가지 녹색 강조를 쓰며 카드 중첩과 강한 장식을 제거했다. 데스크톱의 짧은 개념 장에는 큰 여백이 남는다. 이는 콘텐츠가 오른쪽 반쪽에만 배치되던 결함과 다르지만 추후 통합 레이아웃의 개선 후보이다. check는 뜻·용법·한영 예문을 기본 상태에서 제공한다. 빈도 수치는 원문 메타데이터이고 학습 점수가 아니다.

추가 회귀: 검토 프롬프트의 긴 원문 코드 블록이 작은 화면에서 준비 중으로 빠지는 문제를 실제로 재현했다. 해당 절의 요청 문장을 언어별 의미 단위로 나누어 보존했다. 제목만 남는 페이지를 막기 위해 언어 제목과 뒤 내용을 묶는다. 열린 목차의 화면 회전도 다시 분할하며 포커스를 유지한다. 선택된 글자를 해제하는 터치, 텍스트 선택 중 방향키, Shift+방향키가 장을 이동시키지 않도록 검증했다.

남은 제한: QLoRA처럼 아직 검토되지 않은 긴 원문 코드/ASCII 도식은 화면에 맞는 분할이 없으면 명시적인 준비 중과 원문 경로를 제공한다. 이를 도식 설명의 완성으로 계산하지 않는다. 재배치 시 설명 단위와 분할 장을 유지하지만 동일 단위 안의 정확한 문장 오프셋은 추적하지 않는다. 모든 문서의 모든 장을 모든 크기에서 검토한 것은 아니다.

화면 파일의 수정 전 모바일 viewport는 390×844, 데스크톱은 1280×720이다. 수정 전 PNG는 넘친 영역도 드러내도록 full-page로 저장하여 실제 파일 높이가 viewport보다 크다. 수정 후 PNG는 해당 viewport를 그대로 저장한다. 주요 비교 파일은 `before/watermark-mobile.png` ↔ `after/watermark-ko-390x844.png`, `before/sg-nacl-desktop.png` ↔ `after/sg-nacl-ko-1280x720.png`다. 긴 결과는 `after/statistics-300-390x844.png`, `after/statistics-300-1280x720.png`에서 확인한다.

공통 하네스 피드백은 이 작업에서 재현한 실패에 한정했다. 스킬에 설명상 이점·정적 기본값·필수 의미의 화면 검토·실제 경계 측정·미검토 공개 구분을 반영했다. 별도 무관한 하네스 변경은 하지 않았다. 사용자의 이번 지시가 우선하므로 자동 개선 계약의 커밋·push 절차는 수행하지 않는다.
