# 모바일 스와이프 검토

## 범위와 동작

사용자 후속 요청에 따라 학습·발표 모드에 모바일 좌우 스와이프를 추가했다. 기존 공개 Pages 배포 권한을 유지한다. 원문 한영 Markdown·설명 설계·분할 규칙은 변경하지 않는다. 명세는 스펙012 R18이다.

왼쪽 스와이프는 다음 장, 오른쪽은 이전 장이다. 한 손가락, 60 CSS px 이상, 가로 이동이 세로의 1.5배 이상, 1초 이내 종료인 동작만 인정한다. 본문·제목에서도 사용할 수 있고, 여백 탭·키보드·목차도 유지한다. 처음·끝은 순환하지 않는다.

세로 읽기와 핀치 확대는 브라우저에 맡긴다. 수직 의도가 먼저 드러나면 가로 이동으로 바뀌어도 취소한다. 링크·입력·슬라이더·표·코드·도식의 시작/끝, 텍스트 선택, 마우스 드래그, 다중 터치·취소는 이동에서 제외한다. 터치의 implicit capture 때문에 종료 대상은 실제 좌표의 `elementFromPoint`로 검사한다.

## 검증 증거

기존 생성물에서 실제 CDP 한 손가락 터치를 보낸 실패: `study: real touch left advances exactly one: expected slide 2, got 1`. 로컬 `_workspace/slide-qa/swipe/red.json`에 보존했다. 회귀 스크립트는 `tests/test_slides_swipe_browser.mjs`이며 전체 브라우저 검증에 포함한다.

구현 후 같은 스크립트의 80개 검사가 통과했고 페이지 실행 오류는 없었다. 학습·발표 양방향/경계, 60px/59px, 짧거나 느린/대각선/수직 우선 동작, 12종 시작·종료 제외 대상, 선택·마우스·다중 터치·취소, 학습 모드 실제 세로 스크롤을 포함한다.

`make finalize`가 exit 0으로 완료됐다. 단위155개, 전체166덱 학습/발표 브라우저 검사와 스와이프80개가 통과했고 vault284파일의 byte 검증 pending=0을 확인했다. 로그: `_workspace/slide-qa/swipe-finalize.log`. 공개 배포 후 한영 양쪽 모드의 실제 터치 결과는 최종 응답과 `_workspace/slide-qa/swipe/live.json`에 기록한다.

## 검증 한계

Chromium의 모바일 터치 에뮬레이션은 물리적 iOS/Android 기기와 Safari 실사용 검증을 대체하지 않는다. 핀치 확대는 CSS `pan-y pinch-zoom`으로 허용하며 두 손가락에서 슬라이드가 이동하지 않는 것을 검사한다. OS 가장자리 뒤로가기 제스처의 동작은 기기별 별도 확인 대상이다.
