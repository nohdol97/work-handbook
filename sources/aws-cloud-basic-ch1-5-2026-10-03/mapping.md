# AWS Cloud Basic 1~5장 매핑

- 원문: `aws_cloud_basic_ch01_ch05_source.md`, 3,451행·48,720 bytes. `source.md` 경계 뒤에 업로드 byte를 그대로 보존한다.
- 언어: 한국어 본문과 영어 기술 용어. 한국어 core는 원문 그대로, 영어는 같은 구조의 완역이다.
- 주 영역: AWS 클라우드 기본 구조·네트워크·컴퓨트·스토리지·DB/cache. 전체12장 커리큘럼과 1~5장 통합 구조를 포함한다.
- 신규 정규 문서: `aws-cloud/index.md`, `foundations.md`, `networking.md`, `compute.md`, `storage.md`, `databases-cache.md` 한영6쌍. 기존55쌍에서61쌍으로 확장한다.
- 분류 근거: 기존 한영 경로·정규ID·배포 구조를 재사용한다. 독립 AWS 학습 순서를 플랫폼·인프라 과정에 강제로 끼워 넣지 않는다. 저장소 구조나 배포 방식의 새 아키텍처 결정은 없다.
- 기존 정규 주제: `platform-infrastructure`의 Kubernetes·보안·PostgreSQL·Redis·GPU는 vendor중립 역할을 유지한다. AWS 관리 서비스의 책임·구성·운영조건을 새 과정에서 보존하고 해당 기존 주제로 연결한다. 데이터 플랫폼 object/file/DB 사용 주제도 유지한다.
- 중복 경계: 2장 ALB 보충과3장 LoadBalancer,2장 CIDR/IP 설명 등 원문 반복은 삭제하지 않는다. 새로운 클라우드 자료가 기존 플랫폼 과정의11장완료·다음12장 진도를 대체하지 않는다.
- 추출 순서: 각 장 담당은 본문 작성 전에 상세 개념·예시·수치·조건을 `_workspace`에 추출한다. 통합 담당은소개·커리큘럼·통합구조·진도4항목을 추출한다.
- 읽기 분담: 통합 담당1~73행·3317~3451행; 기본/네트워크74~1686행; 컴퓨트/스토리지1687~2681행; DB/cache2682~3316행. 완성 후 다른 담당이 원문과 양언어 전문을 독립 대조한다.
- 학습 상태: 1~5장은 Basic개념 studied,6~12장은 not-started. 다음은6장 Kubernetes on AWS. AWS계정조회·리소스생성·요금발생·명령실행·장애시험을 수행하지 않는다.

## 원문 전체 읽기·개인정보 검토

모든 담당이 각 배정 구간을 읽었고 접근하지 못한 줄은 없다. Account ID `123456789012`와 ARN, `mydb.xxxxxx...` endpoint, `user:123`, 비용 수치와 public/private IP는 원문에 등장하는 설명용 예시다. 실제 자격증명·개인정보·내부 식별정보는 발견하지 않았다. 문서의 주소로 접속하거나 AWS 자격증명을 사용하지 않았다. 원문48,720byte를 공백 정규화나 삭제 없이 보존한다.

## 정정·적용 범위

공식 AWS 근거와 확인일은 각 장의 원문 밖 보완에 남긴다. IAM권한과trust/SCP, 네트워크 경로와허용,public/zonal NAT와regional/private방식,ALB health제약,EC2/ASG health조건,EBS/EFS/S3종류별가용성·접근,RDS Multi-AZ유형과Aurora endpoint·ElastiCache엔진별동작을 구분한다. 원문의 모든 반복과 단순화는 core에 보존하고 실제검증주장으로 확대하지 않는다.

## 공통 하네스 피드백

기존 전체문서수·원문byte/구간·번역구조·한영검토hash·프롬프트 검증을 재사용한다. 추출 메타데이터의kind목록을 스키마의문자열로 변환해 기존검증오류를 해결했다. 검사기 자체의 결함이나 새 공통동작 변경 필요는 확인되지 않았다. 원문 중간 H1 뒤의 절이 기본 목차에서 누락되는 표시를 재현했고, source밖 바로가기 방식과 확인법은 유지관리 README에 별도 개선으로 문서화한다. 새 분류는 기존 한영 지식구조의 확장이며 새 배포대상·권한·저장소정책을 도입하지 않는다.
