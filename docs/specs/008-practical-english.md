# 스펙 008: 문서 빈도 기반 실전 영어 학습

- 상태: active
- 날짜: 2026-10-05
- 관련 결정: [ADR 008](../adr/008-practical-english.md)

## 문제와 목표

기술 문서를 읽은 뒤 업무·면접에서 영어로 설명할 수 있도록, 기존 전체 문서와 이후 추가 문서의 어휘·표현을 누적 정리한다. 먼저 실제 핸드북 빈도를 집계하고, 한영 뜻·사용 맥락·구어체·예문을 검토해 빈도순 학습 페이지를 제공한다.

## 비목표

일반 영어 전체의 사용 빈도나 CEFR 등급을 측정하지 않는다. 자동 번역·사전 사이트 복제·외부 계정 연결·LLM 호출·사용자 개인 학습 이력 수집은 하지 않는다. 원문 학습 구역과 기존 기술 용어집을 재작성하지 않는다.

## 요구사항과 인수 기준

- R1. 집계 입력은 `docs/en/**/*.md` 전체에서 `english-study/`를 제외한 현재 문서다. front matter·fenced/inline code·HTML comment·URL은 제외하고 제목·목록·표·링크의 표시 문구 등 영어 본문을 센다. 원본 파일은 쓰지 않는다. 임시 문서로 제외·포함·파일 byte 불변을 검사한다.
- R2. 대소문자·curly apostrophe를 정규화하고 명시된 활용형만 합산한다. 구문은 같은 본문 블록 안의 연속 단어만 일치하며 긴 활용형을 우선해 한 항목 안에서 중복 집계하지 않는다. 부분 단어·다른 문단을 이어 붙인 표현은 세지 않는다. count는 출현 횟수, documents는 서로 다른 문서 수다. 동률은 영문 표제어순으로 고정한다.
- R3. `--candidates`는 단어와 2~4단어 연속 구문의 빈도 후보를 출력한다. 이는 검토 후보이며 숙어·자연스러운 표현 판정이 아니다. 빈도 확인 후 검토자가 어휘·숙어/관용 표현·구동사·업무/면접 문장 네 분류의 원고를 관리한다. 최초 반영은 어휘 40개 이상, 다른 분류 각 15개 이상을 제공한다.
- R4. 각 검토 항목에는 고유 ID, 분류, 영문 표제어, 집계 활용형, 한국어 뜻, 사용역, 한영 사용 설명, 영어 예문과 한국어 번역이 있다. 항목의 중복·빈 필드·잘못된 분류·자료형·줄바꿈/Markdown 경계 주입을 거부한다. 숙어와 일반 연어는 설명에서 구별하고, 구어체의 격식 차이와 면접에서 가상 경력을 사실처럼 말하지 않는 조건을 알린다.
- R5. `docs/{ko,en}/english-study/`에 학습 안내와 네 분류 페이지를 생성한다. 각 분류 안에서 출현 횟수 내림차순으로 정렬한다. 0회 항목은 별도 보충 구역에 두며 문서에 나온 표현으로 주장하지 않는다. 전체 코퍼스 수·집계 범위·활용형·빈도와 문서 수·출처 문서 링크를 표시한다. 예문은 작성한 연습용 문장이며 원문 인용·일반 구어 빈도가 아님을 양언어에서 밝힌다. 모바일 읽기를 위해 긴 예문을 넓은 표에 몰아넣지 않는다.
- R6. `scripts/english_study.py --write`는 검토 원고에서 학습 Markdown과 corpus/entry hash가 담긴 `reviews/english-frequency.json`만 갱신한다. 한영 의미 검토 해시는 자동 승인하지 않는다. 기본 `--check`는 읽기 전용으로 원고·코퍼스·생성물 불일치나 누락을 검출해 실패한다. 새 문서·삭제·본문 변경으로 낡아진 집계와 수정된 생성물의 실패를 임시 저장소에서 검사한다. 파일 경로는 고정된 전용 목적지로 제한한다.
- R7. 기존 문서 전체를 최초 집계하고, 이후 문서 추가·변경마다 후보 확인→원고 선별/보완→생성→양언어·예문 검토→전체 검증을 수행한다. `make validate`에서 최신 집계를 검사한다. handbook 계약·원문 보존 skill·한국어 skill 안내·README에 이 반복 절차를 연결한다.
- R8. 완성된 페이지의 한영 의미·빈도 설명·번역·사용역을 독립 검토하고 review hash를 기록한다. 실제 desktop/mobile 화면, 같은 주제 언어 전환, 링크·원문 보존·전체 테스트·vault byte 동기화·기존 승인된 Pages 배포를 확인한다. 자동 빈도 검사는 자연스러운 영어와 학습 효과를 증명하지 않는다.

## 검증 방법

R1–R2·R4·R6은 임시 파일을 사용하는 회귀 테스트로 실패를 재현한 뒤 통과시킨다. R3·R5·R7–R8의 편집 품질은 실제 후보/원고/문서 검토와 화면·전체 검증으로 확인한다. 문서 생성은 결정적이며 재생성한 byte 차이로 누락·수동 수정·정렬 드리프트를 검출한다.
