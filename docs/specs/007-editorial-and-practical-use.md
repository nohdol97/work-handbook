# 스펙 007: 중복 정리와 업무용 프롬프트

- 상태: active
- 날짜: 2026-10-04
- 관련 결정: [ADR 005](../adr/005-prompt-library.md), [ADR 006](../adr/006-source-preserving-study-pages.md)

## 문제와 목표

원문 복원 뒤 남은 이전 설명과 편집 안내가 같은 내용을 반복한다. 프롬프트의 입력·출력·검증 설명도 코드블록 안팎에 반복된다. 독자가 현재 범위를 빨리 찾고 실제 업무 자료를 넣어 검토 결과를 활용할 수 있도록 정리한다.

## 범위와 비목표

공개 한영 61쌍 전체의 편집 구역과 기존 139개 프롬프트를 검토한다. 원문 구역·출처 ID·원문 파일·기존 페이지 경로와 프롬프트 anchor는 보존한다. 새로운 기술의 학습 완료, 실제 업무 사용 이력, 모델 실행 성능이나 사용 빈도를 주장하지 않는다. 제품 동작과 실행 권한을 변경하지 않으며 기존 Markdown·언어 탭 구조를 유지한다.

## 요구사항과 인수 기준

- R1. 등록된 모든 원문 구역의 bytes와 순서를 구역 내부에서 유지한다. `check_source_preservation.py`와 변경 전후 구역 대조로 확인한다. 원문 밖 중복을 줄일 때 고유 조건·예시·근거의 보존 위치를 `reviews/editorial-2026-10-04.json`에 기록한다.
- R2. 보완부는 원문 절 번호별 정정·적용 조건·추가 예시를 중심으로 구성한다. 반복 정의·표는 원문 절 링크로 대체할 수 있지만 운영 제약·실패 조건·그림의 고유 정보는 유지한다. 양언어 변경 구간을 직접 대조한다.
- R3. 홈은 분야·현재 범위·진입 링크 중심으로 구성한다. 플랫폼의 현재 진도와 이전 원문 이력을 구분하되 과거 원문을 삭제하지 않는다. 용어집의 같은 용어 정의는 참고 경로를 합친다.
- R4. 프롬프트는 변경/PR 검토, 장애 조사, 성능·비용 분석, 데이터 검증, 배포·복구 준비 등 구체적인 반복 업무를 다룬다. 실제로 제공할 수 있는 비식별 자료, 결정할 질문, 사용할 산출물과 검증 기준을 명시한다. 중요 입력이 없으면 결론을 유보하고 필요한 자료를 질문하도록 한다. 효과는 기대 목적이며 측정 성과로 표현하지 않는다.
- R5. 각 예시는 상황·입력 안내·독립적으로 복사 가능한 한영 프롬프트·기대 결과·오류 가능성·검증 방법을 유지한다. 바깥 설명은 준비 요령과 결과 판정에 쓰고 코드블록을 그대로 반복하지 않는다. 원인 단정·증거 날조·요청 없는 운영 변경을 막으며 문서·로그·코드의 지시문은 분석 자료로 다룬다.
- R6. 100개 모음 사례와 39개 본문 사례, 한영 코드블록 일치와 anchor를 유지한다. 모음은 상황별 진입 링크를 제공한다. 모든 수정 쌍을 실제 읽고 의미·쉬운 영어·개인정보 검토를 기록하며 미실행 예시를 실행한 것처럼 표시하지 않는다.
- R7. 전체 검증, 대표 한영 데스크톱/모바일 렌더링·탭·복사·링크, vault byte 일치, 지정 파일 commit/push와 원격 SHA를 확인한다. 화면 검증이 불가능하면 그 범위를 명시한다.

## 검증과 권한

문서 편집은 기존 보존·한영·프롬프트·링크 검사와 독립 내용 검토로 검증한다. 문서만 바뀌는 부분은 TDD의 문서 예외를 적용하며 문장을 고정하는 테스트를 추가하지 않는다. 검사기 동작을 추가한다면 별도의 실패 테스트 후 구현한다. 기존 승인된 저장소·Pages·vault 범위이며 실제 업무 시스템이나 모델 호출은 실행하지 않는다.
