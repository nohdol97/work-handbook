# 스펙 004: 사이트 검증과 전달

- 상태: active
- 날짜: 2026-09-24

## 문제와 목표

Markdown 검사가 통과해도 사이트 링크, 언어 전환과 비공개 제어 문서 제외가 실제 HTML에서 실패할 수 있다. 출처 자료 없이 기술 페이지를 꾸며내지 않고 유지관리 페이지부터 검증한다.

## 요구사항과 완료 기준

- R1. `mkdocs build --strict`가 성공한다. 한국어·영어의 같은 주제 언어 선택 링크를 모든 산출물에서 확인한다.
- R2. 실제 HTML의 내부 파일과 anchor 링크가 모두 존재한다. 누락 파일과 fragment에 대한 실패 테스트가 통과한다.
- R3. 공개 HTML은 docs/ko, docs/en 페이지 및 404만 포함한다. sources·운영 계약·ADR·spec·review를 게시하지 않는다.
- R4. 모든 Mermaid fence를 Mermaid parser로 검사한다. 잘못된 문법 입력이 비정상 종료하는 별도 재현으로 확인한다.
- R5. push와 PR에서 같은 테스트·구조·출처·리뷰·Mermaid·strict build·산출물 검증을 실행한다. Pages는 명시적 활성화 변수와 main push 조건을 모두 요구한다. 공개 활성화 전 즉시 확인한다.
- R6. 로컬 `make finalize`는 전체 검증, vault 복사와 읽기 전용 hash 재확인을 순서대로 수행한다. CI는 개인 vault에 접근하지 않는다.
- R7. 자료 반입 절차, 스키마, 쓰기 스타일, 선택적 템플릿, 개인정보와 경험 구분은 handbook-contract에 보존한다. 초기 공개 페이지는 학습 자료 없음과 범위를 양쪽 언어에 명시한다.
- R8. 링크 감사 한 번 안에서 같은 대상 HTML을 중복 파싱하지 않는다. 페이지·anchor가 늘어도 파일별 파싱은 한 번으로 제한하며, 기존의 누락 파일·fragment·경계 검사를 유지한다. 여러 링크가 같은 대상을 참조하는 fixture의 파서 호출 수와 기존 실패 테스트로 검증한다.
- R9. 한국어·영어 모두 데스크톱에서도 모바일처럼 대주제 탐색을 접고 펼친다. 홈에서는 모든 대주제의 하위 목록이 접혀 있고, 대주제를 누르면 펼쳐지고 다시 누르면 접힌다. 문서에서는 현재 문서가 속한 대주제만 기본으로 열린다. 1280px 데스크톱과 375px 모바일의 실제 브라우저에서 홈·문서 초기 상태, 클릭과 문서 이동을 확인한다. 기본 테마 탐색 기능을 사용하며 본문·탐색 순서·언어 전환은 유지한다.
- R10. 사이트 상단에서 시스템 설정·라이트·다크 모드를 전환한다. 첫 방문은 운영체제의 색상 설정을 따르고 수동 선택은 페이지 이동과 다시 열기에서 유지된다. 한국어·영어 홈과 문서에서 동일한 전환을 제공하고 버튼의 접근 가능한 이름에 다음 동작을 명시한다. Material의 기본 palette 기능을 사용한다. `tests/test_theme.py`는 실제 빌드한 양언어 홈·문서의 세 모드와 전환 연결을 검사한다. 브라우저에서는 밝은/어두운 시스템 설정, 수동 전환, 새로고침·문서 이동·언어 전환 후 선택 유지와 본문·코드·표 가독성을 확인한다. 브라우저 검증 불가 시 그 범위를 미검증으로 남긴다.

- R11. 다크 모드에서는 본문·제목·일반 목차·인용문·표·일반 코드 글자를 흰색(`#ffffff`)으로 표시한다. 링크는 밝은 파란색으로 구분하고 코드 구문 강조색은 유지한다. 라이트 모드의 색상은 바꾸지 않는다. 한영 1280px·375px 브라우저에서 계산된 색상과 화면을 확인하고, 변경 전 회색 재현 → 변경 후 흰색 및 라이트 모드 불변을 검증한다.

## 언어 전환 시 읽기 위치

- R12. 같은 주제의 한·영 링크를 일반 클릭하거나 키보드로 실행하면 현재 화면 상단의 읽기 기준선(고정 header 아래 16px)에 있던 본문 구역을 반대 언어에서도 유지한다. 번역된 제목 ID나 전체 문서의 절대 scrollY에 의존하지 않고, 같은 순서의 제목·구역 내 보이는 본문 블록·블록 안의 진행 비율을 사용한다. 문서 맨 위·맨 아래는 그대로 유지한다.
- R13. 문단·목록·코드·표와 제목을 지원하며 숨긴 탭 내용은 위치 계산에서 제외한다. 언어별 블록 구조가 다른 구역에서는 해당 구역 내부 진행률로 대체한다. 제목 구조까지 달라진 경우에는 전체 문서 진행률로 안전하게 대체한다. 레이아웃이 늦게 바뀌면 짧은 초기 복원 기간에만 보정하고, 사용자가 스크롤·터치·키보드 조작을 시작하면 즉시 복원을 중단한다.
- R14. i18n 플러그인이 생성한 같은 주제 링크를 그대로 사용한다. 언어 전환의 다음 목적지와 위치 정보만 탭별 sessionStorage에 최대 60초간 보관하고 목적지에서 한 번 소비한다. 다른 문서 이동·재로드·뒤로가기·수정키 클릭·새 탭 열기·저장소 접근 실패는 기존 링크와 브라우저 동작을 유지한다. 본문·개인정보·계정·서버 저장소는 추가하지 않는다.
- R15. 자동 회귀는 실제 언어 링크 이벤트 → 일회성 전달 → 번역 페이지 스크롤 복원을 검사한다. 한국어→영어→한국어, 번역 제목 ID, 오래된 hash, 다른 문서, 만료·손상 데이터, 저장 실패, 숨긴 탭, 블록 구조 차이와 사용자 개입을 포함한다. 실제 1280px·375px 브라우저에서 제목·문단·긴 코드·표·페이지 끝과 반복 전환을 확인한다. 미검증 환경은 완료 보고에 명시한다.
- R16. 빌드 결과의 모든 한영 페이지 쌍은 읽기 위치 대응에 사용하는 본문 제목 수준 순서가 같아야 한다. 같은 ID의 서로 다른 제목을 잘못 매핑하지 않도록 ID가 아니라 순서로 비교한다. 제목 구조 불일치를 탐지하는 회귀와 전체 사이트 감사로 확인한다.

- R17. Alt+Shift+L(맥: Option+Shift+L)로 현재 문서의 반대 언어를 같은 위치에서 연다. 언어 버튼 tooltip과 aria-keyshortcuts에 안내한다. 검색창·input·textarea·select·contenteditable, IME 조합·키 반복·다른 modifier 조합에서는 실행하지 않는다. 클릭과 같은 복원 경로를 사용하며 양방향 키보드 회귀 및 실제 브라우저로 확인한다.

- R18. 기존 언어 드롭다운 대신 고정된 플로팅 버튼 한 번으로 반대 언어로 전환한다. i18n이 생성한 반대 언어 href를 그대로 사용하고 현재 목적 언어(EN/한), 접근 가능한 이름, 단축키를 안내한다. JS가 실패하면 기본 헤더 언어 메뉴를 유지한다.
- R19. 버튼은 마우스·터치 드래그로 이동하고 드래그 종료는 언어 전환을 일으키지 않는다. 6px 이상 움직일 때 드래그로 판정한다. viewport 안에 여백을 두고 제한하며 리사이즈·모바일 회전 후에도 보인다. 위치만 localStorage에 정규화 좌표로 기억하여 언어 전환·재방문 시 유지하며, 저장이 차단되면 현재 페이지에서 계속 동작한다. 버튼에 키보드 포커스가 있을 때 화살표로 10px(Shift와 함께 40px) 이동할 수 있고 Enter/Space는 언어를 전환한다.

관련 결정은 [ADR 010](../adr/010-language-reading-position.md)을 따른다. 원문 수정·자동 번역·SPA 전환·새 배포 권한은 범위 밖이다. JS 등록을 제거하면 기존 언어 링크 동작으로 돌아간다.

## 범위와 한계

초기 문서·설정은 실제 빌드와 쌍별 직접 검토로 검증한다. 링크 검사는 저장소 안의 렌더된 파일 및 anchor를 검증하며 외부 링크 가용성을 보장하지 않는다. Mermaid 구문 통과는 다이어그램의 기술적 진실을 증명하지 않는다. 초기 문서의 의미 검토는 에이전트가 직접 수행하고 자동 의미 판정으로 표현하지 않는다. 원격 Pages의 실제 배포 결과는 별도로 확인한다.

색상 변경은 사이트 표시 기능에 한정하며 원문·탐색 순서·배포 권한은 변경하지 않는다. 모드 선택은 Material의 기존 브라우저 저장 기능을 따르고 별도 사용자 정보나 서버 저장소를 추가하지 않는다. 설정을 되돌리면 이전 단일 라이트 모드로 복원된다. 구성 근거: [Material 색상·시스템 설정 공식 문서](https://squidfunk.github.io/mkdocs-material/setup/changing-the-colors/).
