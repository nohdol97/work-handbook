# 스펙 004: 사이트 검증과 전달

- 상태: active
- 날짜: 2026-09-24

## 문제와 목표

Markdown 검사가 통과해도 사이트 링크, 언어 전환과 비공개 제어 문서 제외가 실제 HTML에서 실패할 수 있다. 출처 자료 없이 기술 페이지를 꾸며내지 않고 유지관리 페이지부터 검증한다.

## 요구사항과 완료 기준

- R1. `mkdocs build --strict`가 성공한다. 한국어·영어의 같은 주제 언어 선택 링크를 모든 산출물에서 확인한다.
- R2. 실제 HTML의 내부 파일과 anchor 링크가 모두 존재한다. 누락 파일과 fragment에 대한 실패 테스트가 통과한다.
- R3. 공개 HTML은 docs/ko, docs/en 페이지 및 404만 포함한다. sources·운영 계약·ADR·spec·review를 게시하지 않는다.
- R4. 모든 Mermaid fence를 Mermaid parser로 검사한다. 잘못된 문법 입력이 비정상 종료하는 별도 재현으로 확인한다.
- R5. push와 PR에서 같은 테스트·구조·출처·리뷰·Mermaid·strict build·산출물 검증을 실행한다. Pages는 명시적 활성화 변수와 main push 조건을 모두 요구한다. 공개 활성화 전 즉시 확인한다.
- R6. 로컬 `make finalize`는 전체 검증, vault 복사와 읽기 전용 hash 재확인을 순서대로 수행한다. CI는 개인 vault에 접근하지 않는다.
- R7. 자료 반입 절차, 스키마, 쓰기 스타일, 선택적 템플릿, 개인정보와 경험 구분은 handbook-contract에 보존한다. 초기 공개 페이지는 학습 자료 없음과 범위를 양쪽 언어에 명시한다.
- R8. 링크 감사 한 번 안에서 같은 대상 HTML을 중복 파싱하지 않는다. 페이지·anchor가 늘어도 파일별 파싱은 한 번으로 제한하며, 기존의 누락 파일·fragment·경계 검사를 유지한다. 여러 링크가 같은 대상을 참조하는 fixture의 파서 호출 수와 기존 실패 테스트로 검증한다.

## 범위와 한계

초기 문서·설정은 실제 빌드와 쌍별 직접 검토로 검증한다. 링크 검사는 저장소 안의 렌더된 파일 및 anchor를 검증하며 외부 링크 가용성을 보장하지 않는다. Mermaid 구문 통과는 다이어그램의 기술적 진실을 증명하지 않는다. 초기 문서의 의미 검토는 에이전트가 직접 수행하고 자동 의미 판정으로 표현하지 않는다. 원격 Pages의 실제 배포 결과는 별도로 확인한다.
