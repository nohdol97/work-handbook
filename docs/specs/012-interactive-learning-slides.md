# 스펙 012: 공개 학습 문서의 인터랙티브 슬라이드

- 상태: active
- 날짜: 2026-10-18
- 관련 결정: [ADR 014](../adr/014-interactive-slides-pipeline.md), [ADR 015](../adr/015-explanation-first-slides.md)

## 문제와 범위

공개 Markdown은 정확한 한영 학습 본문이지만, 순서·조건·선택의 결과를 직접 확인할 수 없다. 공개 페이지 쌍을 원본으로 삼아 독립 실행 HTML 학습 자료를 만들고, 원문과 대응 관계를 검증한다. 슬라이드는 파생물이며 원문을 수정하지 않는다.

## 요구사항과 인수 기준

- **R1 공개 범위.** MkDocs 공개 탐색에 들어간 `docs/ko`, `docs/en`의 문서만 기본 발견한다. 내부 문서·빌드 산출물·비공개 자료는 제외한다. 상대 경로와 문서 ID가 한영에서 대응해야 하며 누락·중복은 실패로 기록한다. 전체·디렉터리·단일 문서 선택을 검증한다.
- **R2 분석과 추적.** 제목·절·본문·목록·표·코드·링크·원문 지식 ID를 구조화한다. 각 설명 단위는 정확한 원문 절 참조와 근거를 갖는다. 형식적인 학습 목표를 반복하지 않는다. 처리하지 못한 내용은 커버리지 보고서에 남기며 출처 없는 기술 사실·측정값을 생성하지 않는다.
- **R3 스키마 분리.** 문서별 컴포넌트 코드 생성 없이 버전 있는 Slide Schema를 만든다. 문서 ID·경로·언어·제목·절, 목표·개념·설명, 시각화·상호작용과 매개변수, 예제·검증 규칙, 원문 매핑·해설·참고 링크를 포함한다. 스키마 검증 실패는 배포하지 않는다.
- **R4 설명 설계.** 문서 발견과 설명 설계를 분리한다. 표·목록·인용·장애 단어만으로 상호작용을 선택하지 않는다. 기본은 정적 원문이며, 검토된 설명에는 핵심 개념·필요성·조건·관계·예제·한계와 출처를 기록한다. 상호작용에는 정적 설명보다 더 명확히 드러나는 변화와 독립적인 입력→기대 결과가 필요하다. 퀴즈·시험·점수·정오답·암기 카드·필수 편집·완료 측정을 생성하거나 표시하지 않는다. 수치 모델의 가정은 화면에 표시한다.
- **R5 공통 화면.** 밝은 중립 배경·진한 본문·절제된 강조색과 일관된 정렬을 기본으로 한다. 기본 상태에서 필수 설명이 보이며 노트는 보충용이다. 눈에 보이는 이전/다음 버튼 대신 좌우 배경 클릭/탭과 방향키, 접근 가능한 목차 및 보조기술용 탐색을 제공한다. 링크·입력·조작·텍스트 선택·드래그는 장 이동을 일으키지 않는다. 처음과 끝에서 순환하지 않는다.
- **R6 빌드.** 개별 HTML은 `file://`에서 동작하는 standalone 파일로 만든다. 콘텐츠 해시와 엔진 버전으로 변경분만 재생성하고, 테마/렌더러 변경은 전체를 다시 생성한다. 실패 문서의 이전 정상 산출물은 유지하되 실패를 명시하고 새 인덱스에는 성공한 문서만 표시한다. 전체 재빌드를 지원한다.
- **R7 사이트 연결.** MkDocs 빌드 후 생성된 공개 원문 페이지에 대응 슬라이드 링크를 넣고, 슬라이드에는 원문과 관련 문서 링크를 넣는다. 한영 URL·탐색 구조를 유지하며 내부 운영 문서는 여전히 게시하지 않는다. 로컬 vault에는 원본 Markdown만 복사한다.
- **R8 검증.** 원본 ID·경로·절·지식 ID 커버리지, 한영 링크, 실패 목록을 기계 판독 보고서로 제공한다. 대표 유형과 전체 산출물에 대해 브라우저 렌더링·내비게이션·입력→출력·초기화·화면 크기·오류·오프라인 실행·키보드 조작을 검사한다. 자동 의미 검증이 증명하지 못한 기술적 정확성은 대표 원문과 전문을 직접 대조해 별도 보고한다.
- **R9 확장.** 문서 어댑터, 분석기, 학습 설계기, 시각화/상호작용 레지스트리, 렌더러, 내보내기, 검증기의 경계를 분리한다. 새 유형은 기존 문서별 코드 복제 없이 등록 가능해야 한다. 최초 버전은 서버·DB를 필요로 하지 않는다.

## 비목표

- 원문을 다시 쓰거나 새로운 학습 사실을 보충하지 않는다.
- 원본에 근거가 없는 수치 시뮬레이션이나 실제 운영 결과를 꾸미지 않는다.
- PDF/PPTX·학습 기록 서버는 인터페이스만 열어 두고 이번 배포에는 포함하지 않는다.

## 확인 방법

단위 테스트의 실패→통과, 전체 한영 변환 보고서, strict MkDocs·사이트 감사, 대표 문서의 원문 대조, 실제 브라우저와 `file://` 조작, `make finalize`의 vault byte 검사를 함께 확인한다. 원문 내용의 모든 의미를 자동으로 증명할 수 없으므로 자동 커버리지와 직접 의미 검토를 구분한다.

## 설명 우선 개정의 추가 기준

- **R10 의미 보존.** 표의 행/열 머리글·셀·링크, 도식의 간선·방향·포함 관계를 보존한다. 의미를 알 수 없는 도식을 버튼 격자로 바꾸지 않는다. 탭·코드·인용은 구조화해 원시 Markdown 표식 노출을 막는다. 필수 정의·조건·예제의 화면 존재와 출처 추적은 별도로 검사한다.
- **R11 모드별 읽기.** 웹 기본값은 학습 모드다. 같은 원문 절의 정의·관계·예제·조건·한계를 한 페이지에서 이어 읽게 하며 페이지 세로 스크롤을 허용한다. 화면 높이에 맞추려고 설명을 작은 장으로 분해하지 않는다. 중첩 스크롤·가로 overflow·잘림·말줄임·읽기 어려운 축소는 금지한다. 발표 모드는 헤더·본문·탐색을 포함해 한 화면에 맞추고 의미 단위로 분할한다. 목차/노트 overlay는 두 모드 모두 포커스·읽기 가능 영역을 보존한다. 320×568, 390×844, 768×1024, 1280×720, 모바일 가로·글자 확대·회전을 검사한다.
- **R12 위치와 접근성.** 안정적인 절/설명 단위 ID로 새로고침·뒤로가기·언어 전환·반응형 분할 위치를 유지한다. 한영 제목 문자열이나 슬라이드 순번은 대응 키가 아니다. 목차/노트는 포커스 진입·가두기·Escape·닫은 뒤 복귀를 제공한다. 조작부 방향키와 전역 이동은 충돌하지 않는다.
- **R13 대표 검토.** Watermark, SG/NACL, Schema Break, 영어 check, 실무 프롬프트, QLoRA 전체 흐름을 한영 원문과 대조한다. 각 설명의 무엇/왜/어떻게/예제 결과 이유를 기본 화면에서 따라갈 수 있어야 한다. Foundations Statistics는 min=100, max=500, 조건 > 기준값에서 300은 읽을 가능성, 500/1000은 건너뛰기, 초기화는 1000이다. 가능성을 실제 데이터 존재로 단정하지 않는다.
- **R14 검증 경계.** 전체 페이지 로딩과 대표 설명의 기술·디자인·명료성 검토를 따로 보고한다. 생성 개수·상호작용 수·원문 행 커버리지는 설명 품질 증거가 아니다. 미검토 설명은 정적 원문 또는 명시적인 준비 중 상태로 제공한다. 화면 읽기 프로그램 실사용과 이해도 향상은 실제 측정 전에는 검증됐다고 주장하지 않는다.
- **R15 작업 권한.** 2026-10-18 후속 요청은 기존 공개 Pages로의 커밋·push·배포를 승인했다. 배포 전 전체 검증·vault byte 검증·변경 범위/공개 정보 검토를 수행하고 배포된 SHA와 실제 웹 화면을 확인한다. 정규 한영 Markdown은 변경하지 않는다.
- **R16 모드 위치.** 학습/발표 전환·언어 전환·새로고침·뒤로/앞으로 이동에서 설명 절/단위와 모드를 유지한다. 학습 모드의 페이지 스크롤·텍스트 선택·링크/입력은 절 이동을 일으키지 않는다. 긴 절은 읽던 설명 단위로 이동한다. 화면 회전은 열려 있는 설명 도구와 입력값·결과도 유지한다.
- **R17 확장 감사.** 공개 전체 문서의 학습 모드 각 절을 읽기 전용으로 순회하여 준비 중 대체·가로 넘침·중첩 스크롤·잘린 콘텐츠와 원문 텍스트 누락을 검사한다. 검토된 설명 유형은 한영 의미·기술·시각 검토를 별도로 수행한다. QLoRA 흐름은 원문의 10개 단계·9개 방향 관계와 이후 절 근거의 이유·예시·한계를 보존한다. 전체 구조 검사를 전 문서의 전문 기술 검토나 사용자 이해도 측정으로 표현하지 않는다.

검증 표면: `tests/test_interactive_slides.py`는 구조·원문·설계 경계를, `tests/test_slides_browser.mjs`는 독립 기대 결과와 발표 화면/탐색을, `tests/test_slides_study_browser.mjs`는 전체 학습 절의 가시 텍스트와 배치·모드 전환을 검사한다. 직접 재현·화면·미검증 범위는 별도 검토 기록에 남긴다.

## R18. 모바일 스와이프 탐색

학습·발표 모드에서 한 손가락으로 본문 또는 여백을 왼쪽으로 스와이프하면 다음 장, 오른쪽이면 이전 장으로 한 번만 이동한다. 60 CSS px 이상, 가로 이동이 세로 이동의 1.5배 이상이고 1초 이내에 끝난 동작만 인정한다. 첫·마지막 장은 순환하지 않는다. 기존 여백 탭·방향키·목차는 유지한다.

세로 스크롤, 짧거나 대각선인 동작, 마우스 드래그, 선택된 텍스트, 다중 터치, 취소된 포인터는 이동하지 않는다. 링크·버튼·입력·슬라이더·도식·표·코드에서 시작하거나 끝나는 동작은 제외한다. 핀치 확대와 학습 모드의 기본 세로 읽기를 막지 않는다. 한영 안내에 스와이프를 표시한다.

검증: `tests/test_slides_swipe_browser.mjs`에서 모바일 브라우저 터치로 양방향·경계·세로 읽기를 검사하고 제외 대상·다중 터치·취소·선택·마우스 드래그를 회귀 검사한다. 실제 iOS/Android 기기의 제스처 동작은 별도 미검증 범위로 보고한다. 원문·설명 설계·페이지 분할은 변경하지 않는다.

## R19. 정적 도식 안내문 제거

학습 모드의 Mermaid 또는 문자 도식 앞에 렌더러가 덧붙이던 정적 원문 안내문을 한영 모두 표시하지 않는다. 원문 도식과 그 밖의 본문은 유지한다. 브라우저에서 도식의 원문 텍스트가 보이고 해당 안내문이 보이지 않는지 확인한다.
