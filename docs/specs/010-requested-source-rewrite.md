# 스펙 010: 명시 요청에 따른 원문 본문 개정

- 상태: active
- 날짜: 2026-10-18
- 관련 ADR: [012](../adr/012-scoped-source-rewrite.md)

## 문제와 범위

기존 등록 원문을 그대로 두고 설명만 덧붙이면 중간의 어려운 문장이 남는다. 사용자는 `data-platform` 문서 전체의 기존 본문 문장도 쉽게 고치고, 앞으로 이 스킬을 사용하는 문서에도 같은 방식을 적용하도록 명시했다. 원본 자료의 추적성과 이번에 선택하지 않은 영역의 원문 보존은 유지한다.

## 목표

- `data-platform` 한영 문서의 등록된 본문을 직접 개선한다. 기존 목차·번호·순서, 모든 의미 있는 기술 사실·조건·예시·코드·표와 지식 ID를 유지한다.
- 원본을 `sources/`에 보존하고 등록 관계를 유지한다. 개정 본문은 한영으로 읽고 원본과 대조한다.
- 이후 스킬을 사용하는 문서 작업에서는 선택된 등록 구역을 개정 모드로 전환한다. 이번 문서 편집은 `data-platform`에 한정한다.

## 비목표

- 다른 영역의 원문 보존 모드를 변경하지 않는다.
- 자동 검사로 의미 보존·번역 품질·가독성을 승인하지 않는다.
- 출처의 검증되지 않은 제품 주장을 현재 사실로 조용히 바꾸지 않는다.

## 요구사항과 인수 기준

- **R1. 선택 범위.** 등록 구역은 선택되기 전까지 원문 byte 동일성 검사 대상이다. 이 스킬로 문서를 작성·개정하면 선택된 등록 구역에 `preservation_mode: editable`과 공개 가능한 2026-10-18 사용자 상시 지시·현재 작업 범위 증거를 기록한다. 명시적 verbatim 요청은 예외다. 잘못된 모드·빈 증거·경로 오류는 실패한다. 이번 전환은 `data-platform/` 등록 구역에 한정한다. 기존 보존 회귀와 새 모드의 거부 회귀로 확인한다.
- **R2. 구조와 원본.** 개정 모드는 원본 파일·구역 경계·페이지 경계를 유지한다. 원본과 한영 개정 구역의 제목 깊이와 번호 순서, fenced block 종류와 순서, 목록·표·인용·구분선의 형태와 순서를 검사한다. 제목·코드 경계·목록·표 등의 누락, 빈 본문, 한영 구조 불일치는 실패한다. 문장과 문단 표현은 의미를 유지하며 수정할 수 있다. fixture의 red→green 검사와 원본 파일 불변 확인으로 검증한다.
- **R3. 직접 개정.** 각 문서의 기존 본문 문장을 쉬운 표현으로 고치며 첫 용어 풀이, 적절한 비유·실제 예시, 정의·이유·사용 시점·기술 연결을 필요한 절 안에 둔다. 도입부뿐 아니라 이해하기 어려운 중간 개념과 선택 기준에도 일상 비유를 찾아 적용하고, 곧바로 실제 기술 의미·조건과 연결한다. 억지 비유와 반복은 피한다. 공개 문서 상단의 `문서 유형`·`본문 안내` 같은 편집 메타 안내는 싣지 않고, 중요한 적용 범위와 검증 한계는 관련 설명에 남긴다. 원래 기술 주장·제약·반례·절차·예시를 빠뜨리지 않고 반복을 줄인다. 양언어 전체 문서와 원본을 직접 대조하고, 기존 장별 핵심 정리를 유지한다.
- **R4. 검토와 전달.** 22개 한영 문서의 실제 의미 검토 기록과 hash를 갱신한다. 영어 학습 후보·생성물을 검토한다. 전체 보존 검사, `make validate`, 대표 화면·언어 전환, `make finalize`의 vault byte 일치가 통과해야 한다.

## 권한과 되돌리기

사용자의 현재 명시 요청은 `data-platform` 문서와 관련 스킬·계약·검사 변경을 승인한다. 앞으로 스킬을 적용할 때는 그 작업에서 선택한 문서만 개정한다. 다른 등록 구역은 기존 모드 그대로다. 문제가 발견되면 해당 문서와 등록 모드만 이전 커밋 기준으로 복구할 수 있으며 `sources/`의 원본은 수정하지 않는다.
