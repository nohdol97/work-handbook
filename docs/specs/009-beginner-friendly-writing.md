# 스펙 009: 입문자가 이해할 수 있는 문서 작성

- 상태: active
- 날짜: 2026-10-17
- 관련 ADR: [011](../adr/011-accessible-writing-and-source-boundaries.md)

## 문제

기존 원문 보존 규칙은 출처 누락을 막지만, 어려운 표현을 쉽게 풀어 쓰는 새 문서 작업에는 그대로 적용하기 어렵다. 사용자는 앞으로 기존 목차와 핵심 기술 내용을 유지하면서 입문서처럼 읽히는 설명을 원한다.

## 목표

1. 새 문서와 이후 개정 문서에서 원래 목차·핵심 지식의 추적성을 지키면서 쉬운 설명을 제공한다.
2. 이미 등록된 원문 동일성 검사를 임의로 우회하지 않는다.

## 비목표

- 기존 전체 페이지를 이번 변경에서 일괄 재작성하지 않는다.
- 자동 검사만으로 기술적 정확성이나 가독성을 승인하지 않는다.

## 요구사항

### R1. 적용 경계

앞으로 새로 작성하거나 개정하는 설명에는 이 기준을 적용한다. 사용자가 지정한 기존 목차와 순서, 핵심 기술 사실·조건·예시를 유지한다. 원본 자료는 `sources/`에 공개 가능하게 정리해 보관하고 기존 ID 추적을 유지한다. `reviews/source-preservation.json`에 등록된 기존 원문 구역은 명시적인 해당 구역 개정 요청이 없는 한 동일성 검사를 유지한다. 그 구역의 쉬운 설명은 우선 경계 밖 보완부에 둔다.

명시적인 등록 본문 개정 요청은 [스펙 010](010-requested-source-rewrite.md)의 범위 한정 등록·검증을 따른다.

### R2. 문장과 용어

어려운 표현은 정확성을 잃지 않는 쉬운 언어로 바꾼다. 표준 전문 용어는 유지하고 첫 등장에 짧게 풀이한다. 한국어와 쉬운 영어의 설명 범위가 같아야 한다.

### R3. 설명의 흐름

추상적 개념은 적절한 일상 비유와 구체적인 기술 예시로 설명한다. 비유의 한계가 중요한 경우 밝힌다. 정의와 함께 왜 필요한지, 언제 쓰는지 설명하고 관련 기술과 실제 활용 흐름을 연결한다. 근거 없는 경험·측정·운영 주장을 만들지 않는다.

### R4. 완전성과 간결성

기존 의미 있는 내용을 누락하지 않고 이해에 필요한 설명을 보강한다. 같은 정의나 예시를 불필요하게 반복하지 않고, 설명이 핵심 내용보다 길어지지 않도록 검토한다. 기존 장 구분이 있는 문서는 각 장 끝에 짧은 핵심 정리를 둔다. 장 구분이 없는 문서에는 억지로 장을 만들지 않는다.

### R5. 검토와 전달

작성자는 원본·목차·양언어 전체를 직접 대조해 누락, 기술적 정확성, 초보자 가독성, 비유의 적절성, 장별 정리, 개인정보를 검토한다. 기존 원문 등록 페이지는 보존 검사도 통과해야 한다. 변경된 영어 페이지는 실전 영어 후보와 생성물을 갱신한다. `make validate`, 렌더링 점검, `make finalize`의 vault byte 검증 후 완료한다.

## 완료 기준

1. 계약·스킬·README가 R1–R4의 동일한 적용 경계와 작성 기준을 설명한다.
2. 기존 원문 등록·동일성 검사 규칙은 유지되고, 새 작성 방식이 이를 우회하라는 지시를 포함하지 않는다.
3. 변경 문서의 직접 대조와 `python3 scripts/check_harness.py`, 전체 단위 테스트, `make validate`, `make finalize`의 결과를 기록한다.

## 미검증 범위

- 이번 변경은 작성 지침을 정한다. 미래 문서의 실제 난이도와 비유의 품질은 해당 작성 작업에서 전문 검토한다.
