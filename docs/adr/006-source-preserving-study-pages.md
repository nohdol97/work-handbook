# ADR 006: 학습 원문의 형태 보존과 보완 분리

- 상태: accepted
- 날짜: 2026-09-27

## 배경

사용자는 Lakehouse·Iceberg처럼 제공한 Markdown의 구조를 따라 읽기를 원한다. 6~14장 등은 개념 연결을 보존했더라도 소절·예시를 합치고 문단을 압축해 이 요구를 충족하지 못했다. 원문은 거의 복사·붙여넣기 수준으로 보존하고 추가 설명만 덧붙이라는 지시가 기준이다.

## 결정

원문 중심 학습 문서는 원문의 제목·번호·순서·문단·목록·표·코드 블록을 보존한다. 원래 언어의 원문 구역은 저장된 source 구간과 직접 비교하고, 반대 언어는 동일한 구조로 번역한다. 정정·현재 버전 조건·추가 그림·실무 예시는 별도 보완 구역에 둔다. 원문의 오류도 조용히 덮어쓰지 않는다.

기존 지식 ID·경로·언어 쌍·배포 방식은 유지한다. 보존 범위는 `reviews/source-preservation.json`에 명시하고 원문의 고유한 시작·끝 제목으로 찾는다. 자동 검사는 원문 동일성과 문단·제목·목록·표·인용·구분선·fence 구조만 확인하며 의미·가독성은 직접 검토한다.

## 대안과 결과

- 지식 ID와 coverage만 확인: 원문의 표현과 학습 순서 파괴를 감지할 수 없어 불충분하다.
- 합쳐진 절 앞에 번호만 추가: 원래 소절의 범위와 예시 구분이 돌아오지 않아 제외했다.
- 원문을 사이트 밖에만 보관: 사용자가 읽는 학습 페이지의 문제를 해결하지 못한다.

문서 길이는 늘어나지만 원문을 직접 대조할 수 있다. 검토자는 원문과 추가 설명을 구분하고 부정확한 원문의 적용 조건을 보완 구역에서 명시해야 한다. 이번 결정은 새 권한이나 공개 대상을 추가하지 않는다.

## 검증

[스펙 006](../specs/006-source-preservation.md), 보존 검사 회귀 테스트, 원문·한영 전문 대조, 렌더링·언어 전환·vault byte 확인으로 검증한다.

Markdown의 trailing spaces는 원문 hard break일 수 있으므로 `.gitattributes`에서 Markdown에 한해 blank-at-eol 경고를 끈다. 실제 공백은 원문 구간 동일성 검사로 보호하며 다른 diff 오류 검사는 유지한다.
