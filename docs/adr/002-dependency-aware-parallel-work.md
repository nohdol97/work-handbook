# ADR 002: 의존성 기반 병렬 작업

- 날짜: 2026-09-24
- 상태: accepted

## 배경

서로 독립적인 조사, 검증과 구현을 순차 실행하면 결과 사이에 불필요한 대기 시간이 생긴다. 모든 작업을 무조건 병렬화하면 같은 파일이나 외부 상태의 동시 변경, 미결정 판단의 불일치, 순서가 필요한 검증의 왜곡이 발생할 수 있다.

## 결정

- 비자명한 작업을 시작할 때 의존 관계와 공유 변경 표면을 확인한다.
- 독립적이고 의미 있는 작업 단위가 둘 이상이면 사용 가능한 동시성 범위에서 병렬 실행한다.
- 구체적이고 범위가 제한되며 서로 겹치지 않는 하위 작업은 보조 에이전트를 사용할 수 있을 때 위임한다.
- 같은 파일·외부 상태를 변경하거나, 미결정 공통 판단에 의존하거나, 순서가 검증 의미를 결정하는 작업은 직렬화한다.
- 조율 비용이 이득보다 큰 작은 작업은 직접 수행한다.
- 주 에이전트가 계획, 권한 판단, 통합, 충돌 해소와 최종 검증을 책임진다.

## 대안

- 모든 작업을 무조건 병렬화: 최대 동시성은 얻지만 충돌과 잘못된 검증을 막지 못해 기각했다.
- 병렬화를 선택 사항으로만 둠: 순차 실행이 기본값이 되어 독립 작업의 대기 시간을 안정적으로 줄이지 못하므로 기각했다.
- 전용 병렬 실행 스킬 추가: 항상 적용되는 짧은 운영 규칙에 별도 트리거와 자산을 추가할 이유가 부족해 기각했다.

## 결과

- 독립 작업의 대기 시간이 줄고 사용 가능한 동시성을 일관되게 활용한다.
- 작업 분해와 결과 통합 비용이 추가된다.
- 공유 변경과 외부 부작용은 직렬화되어 기존 안전·권한 경계를 유지한다.

## 영향과 검증

- 영향: `AGENTS.md`, 한국어 요약, README, 기본 스펙과 작업 계획
- 검증: `python3 scripts/check_harness.py`와 생성 회귀 테스트로 계약·문서 동기화를 확인한다.
