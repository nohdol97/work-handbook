# ADR 015: 설명 우선 슬라이드와 검토 경계

- 상태: accepted
- 날짜: 2026-10-18
- 관련: ADR 014의 파이프라인 유지, 스펙 012 R4–R5 개정 및 R10–R17

## 맥락

Markdown 모양을 의미로 간주한 변환은 SG/NACL 머리글을 잃고 링크 색인을 번호 퀴즈로 바꿨다. Watermark 필수 조건은 노트에만 남았으며 좁은 화면의 두 열 구성은 본문을 읽을 수 없게 만들었다.

## 결정

공개 문서 발견, 원문 분석, 설명 설계, 검토 가능한 데이터, 공통 렌더러, 검증을 분리한다. 자동 발견은 모든 문서에 적용하지만 상호작용은 근거와 설명상 이점이 검토된 경우에만 등록한다. 기본 결과는 정적 원문이다. 검토된 대표 설명은 한영 공통 ID와 출처·가정을 가진다. 퀴즈·채점·카드 뒤집기·필수 편집은 제거한다.

후속 사용자 요청에 따라 웹 기본값은 학습 모드로 한다. 같은 절의 설명을 모아 페이지 세로 스크롤로 이어 읽게 한다. 발표 모드만 실제 가용 화면에 따라 나눈다. 위치는 모드와 설명 단위 ID에 연결한다. 목차와 노트는 두 모드에서 모두 읽기·포커스 경계를 유지한다. 표의 머리글과 도식의 관계를 의미의 일부로 취급한다.

## 대안과 결과

모든 문서에 자동 인터랙션을 붙이면 수는 늘지만 의미 오류를 숨긴다. 모든 절에 수작업 시뮬레이터를 만들면 검토 비용과 기술 오해가 늘어난다. 정적 기본값과 선별된 설명은 확장 속도가 느리더라도 미검토 상태를 솔직하게 유지한다. 화면 분할은 페이지 수를 늘리므로 안정적인 ID와 언어 대응을 별도로 관리해야 한다.

## 영향과 검증

생성기·설명 데이터·공통 렌더러·스킬·스펙·단위/브라우저 검증을 변경한다. 정규 Markdown은 유지한다. 후속 사용자가 기존 Pages 배포까지 승인했으므로 전체 검증 뒤 배포 SHA와 live 결과를 확인한다. 전체 로딩, 대표 설명의 원문 의미, 입력→기대 결과, 화면 경계와 접근성을 서로 다른 증거로 기록한다. 사용자 이해도는 실제 사용자 검증 전에는 측정된 효과로 보고하지 않는다.
