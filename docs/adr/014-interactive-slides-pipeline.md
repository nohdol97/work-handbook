# ADR 014: 공개 문서에서 스키마를 거쳐 독립 HTML 슬라이드 생성

- 날짜: 2026-10-18
- 상태: accepted
- 관련 스펙: [012](../specs/012-interactive-learning-slides.md)

## 배경

한영 Markdown과 MkDocs 탐색이 정규 지식이다. 문서별 React 코드를 새로 만들면 83쌍의 수정·추적 비용이 크다. 기존 사이트 검사는 정규 페이지 외 HTML을 차단한다.

## 결정

공개 탐색과 한영 front matter ID를 발견의 기준으로 삼는다. 파서는 원문 절과 근거를 보존하는 Slide Schema를 생성한다. 공통 렌더러가 이를 standalone HTML로 만든다. 별도 플러그인은 원문으로 검증 가능한 특수 상호작용에만 사용한다. 생성 HTML·보고서는 원본과 분리하고, MkDocs 빌드 후 사이트에 복사하여 양방향 링크를 만든다. 사이트 검사는 허용된 슬라이드 경로와 대응·링크를 추가로 검증한다. 기존 Pages 권한·조건을 따른다.

오픈소스 `slides-generator`의 고정된 React 디자인·내비게이션·standalone 빌드 구성 중 검토된 부분을 재사용하고, `interactive-slides`의 교육 상호작용 지침은 설계 참고로 쓴다. 외부 Skill 자체 자동 설치는 기존 allowlist·감사 정책을 충족할 때만 한다.

## 대안과 결과

문서마다 JSX를 생성하면 표현 자유도는 크지만 수정 때 전체 재생성이 필요하다. MkDocs Markdown에 슬라이드를 직접 넣으면 원문 보존 경계를 흔든다. 공통 스키마는 일부 고급 시뮬레이션에 플러그인이 필요하고 의미 검토 비용을 없애지 못하지만, 원문 추적과 전체 빌드가 일정해진다.

## 영향과 검증

새 Skill, 생성기, 빌드·CI·사이트 검사, 인덱스와 보고서가 추가된다. [스펙 012](../specs/012-interactive-learning-slides.md)의 R1–R9 및 전체 기존 검증·vault 검사를 따른다. 생성 단계가 실패하면 이전 배포 가능 결과와 실패 목록을 구분한다.
